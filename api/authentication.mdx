The InkLoom API authenticates every request using API keys passed as Bearer tokens in the `Authorization` request header. There are no cookies, sessions, or OAuth flows — every call to the API must include a valid key for authentication to succeed.

## Get Your API Key

Generate an API key from the InkLoom dashboard before making your first request.

<Steps>
  <Step title="Log in to the InkLoom dashboard">
    Navigate to [app.inkloom.io](https://app.inkloom.io) and sign in to your account.
  </Step>
  <Step title="Open API Keys settings">
    Go to **Settings** → **API Keys** from the left-hand navigation.
  </Step>
  <Step title="Create a new API key">
    Click **Create API Key** to open the key creation dialog.
  </Step>
  <Step title="Name your key">
    Give the key a descriptive name that identifies how it will be used — for example, `CI/CD Pipeline`, `GitHub Action`, or `Local Dev`. A clear name makes it easier to audit and revoke keys later.
  </Step>
  <Step title="Select scopes">
    Choose the scopes this key needs. Grant only the permissions your integration requires. See [Scopes](#scopes) below for the full list.
  </Step>
  <Step title="Copy the key immediately">
    After creation, copy your API key and store it in a secure location. **The key is shown only once** and cannot be retrieved from the dashboard again.
  </Step>
</Steps>

## Use Your API Key

Pass your API key in the `Authorization` header of every request using the `Bearer` scheme.

```bash
curl https://api.inkloom.io/v1/projects \
  -H "Authorization: Bearer ik_live_xxxxxxxxxxxx"
```

Replace `ik_live_xxxxxxxxxxxx` with your actual API key. The header must be included on every request — the API is stateless and does not maintain sessions.

## API Key Format

InkLoom API keys follow a consistent prefix convention that makes them easy to identify:

| Prefix      | Environment | When to Use                                             |
| ----------- | ----------- | ------------------------------------------------------- |
| `ik_live_`  | Production  | Use in deployed applications and production pipelines.  |
| `ik_test_`  | Test        | Use during development and testing. No live data is affected. |

<Tip>
  Use `ik_test_` keys during local development and CI testing so that any accidental misuse never touches your live documentation projects.
</Tip>

## Scopes

Scopes define the exact permissions granted to an API key. When you create a key, select only the scopes your integration needs — this limits the blast radius if the key is ever leaked.

| Scope               | Permission Granted                                 |
| ------------------- | -------------------------------------------------- |
| `projects:read`     | Read project metadata and settings.                |
| `projects:write`    | Create, update, and delete projects.               |
| `pages:read`        | Read page content and metadata.                    |
| `pages:write`       | Create, update, and delete pages.                  |
| `deployments:write` | Trigger and manage deployments.                    |

<Info>
  A key with `deployments:write` can trigger a deployment, but it cannot modify page content unless `pages:write` is also granted. Scopes are independent and additive.
</Info>

## Revoking an API Key

Revoke a key immediately if it is no longer needed, may have been exposed, or belongs to a departing team member.

1. Go to **Settings** → **API Keys** in the InkLoom dashboard.
2. Find the key you want to revoke.
3. Click **Revoke** next to the key and confirm the action.

Revoked keys stop working **immediately** — any in-flight requests using a revoked key will receive a `401 unauthorized` response.

<Warning>
  **Never commit API keys to source control.** A key pushed to a public repository should be treated as compromised — revoke it immediately and generate a replacement.

  Store API keys in environment variables, a secrets manager, or a service like **GitHub Secrets** or **AWS Secrets Manager**. Reference the key by variable name in your code rather than hardcoding its value.
</Warning>

## Authentication Errors

If the API cannot authenticate your request, it returns one of the following errors:

| HTTP Status | Code           | Cause & Resolution                                                                                     |
| ----------- | -------------- | ------------------------------------------------------------------------------------------------------ |
| `401`       | `unauthorized` | The `Authorization` header is missing, the token format is invalid, or the API key has been revoked. Verify the header is present and the key is valid. |
| `403`       | `forbidden`    | The API key is valid but does not have the scope required for this endpoint. Edit the key's scopes or create a new key with the necessary permissions. |
